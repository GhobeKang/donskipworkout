리포트에 근육별 운동 빈도 지도 추가

목적은 자주 기록한 부위와 타겟 기록이 적은 부위를 한눈에 비교하고, 다음 운동에서 확인할 누락 후보를 찾는 것이다. 인체의 포즈보다 근육 윤곽, 기록과 도형의 연결 정확도, 저빈도와 고빈도의 시각적 차이를 우선한다.

권장안: 근육별로 분리한 2D 벡터 도형 + 명시된 타겟의 운동일 빈도 + 고정된 단일 계열 색상 척도.

앞·뒤 인체 도식에 근육별 SVG 경로를 배치하고 region_key로 운동 기록을 연결한다. 빈도가 높을수록 채도는 높이고 명도는 낮춘다. 세부 부위를 알 수 없는 기록은 점선 범위로, 데이터 부족은 사선 패턴으로 구분한다.

앱·서버·DB 구현은 하지 않았다. 부위별 PNG 시안 3장 이후, 가슴 원본을 실제 SVG 6파츠로 분리한 동작 샘플을 추가했다. 전체 인체 벡터와 실제 운동 기록 연결은 아직 완료하지 않았다.

실제 작업 샘플: 가슴 좌우 2파츠를 6파츠로 분리

공개 코드의 가슴 좌우 경로를 가져와 각각 윗·가운데·아랫가슴으로 분할했다. 직사각형 마스크나 AI 이미지 분할을 사용하지 않고, 원본의 외곽 곡선을 유지한 여섯 개의 닫힌 Bézier 경로로 만들었다.

가슴 파츠 선택·빈도 변경 샘플 열기 · 실제 파츠 데이터·채색 코드 · 분리 SVG

미리보기는 SVG를 직접 렌더링한 PNG이며 생성형 AI 이미지가 아니다. 그림 파츠는 여섯 개이고 집계 키는 윗·가운데·아랫가슴 세 개다. 소흉근은 별도 심부 도식이 필요하다. 분할 경계는 타겟 구역 시안이며 해부학적으로 검증된 독립 근육 경계가 아니다.

한 파츠만 변경, 동일 구역 좌우 변경, 클릭한 파츠 ID 선택, 모든 경로의 좌표 유지 검증을 통과했다. 원본 외곽과의 겹침·누락·범위 초과는 좌우 합계 4,732개 표본점에서 검출되지 않았다. 실제 브라우저 자동 상호작용 검증은 file URL 정책으로 수행하지 못했으며, 컨트롤러는 DOM 모델로 검증했다. 앱 리포트와 DB에는 아직 연결하지 않았다.

핵심 보완: 그림을 생성하는 것이 아니라 고정 파츠에 데이터를 연결한다

생성한 PNG는 부위별 ID·경로·마스크를 포함하지 않는다. 따라서 그 파일만으로는 근육을 따로 선택하거나 실제 빈도에 따라 다시 칠할 수 없다. 앞서 만든 샘플은 그림의 외관 참고이며, 실제 리포트용 자산의 제작·매핑 검증을 대신하지 못했다.

제품의 원본은 처음부터 편집 가능한 파츠별 SVG로 제작한다. 제작 완료 후에는 윤곽과 좌표를 고정하고, 리포트 생성 시 해당 파츠의 fill과 상태 표시만 바꾼다. 리포트 생성 과정에 이미지 생성 AI나 이미지 영역 추론을 넣지 않는다.

제작할 때 한 번
  파츠 사전 → 편집 가능한 SVG 원본 → 경로·ID 검증 → 런타임 경로 데이터

리포트마다
  운동 기록 → 표준 부위 키 → 서로 다른 운동일 수
          → 고정 파츠 ID 목록 → fill 변경 → 화면·PNG 공유

빈도가 바뀌어도 path의 d, 좌표, 경계, 크기는 바뀌지 않는다.

이미지 제작을 실행 가능한 작업으로 분리

  1. 파츠 사전을 먼저 작성한다. 입력 분류 40개 각각에 집계 키, 부모 그룹, 필요한 시점, 좌우 파츠 ID를 명시한다. “40개 분류”와 “40개 경로”를 같은 것으로 취급하지 않는다. 좌우·다중 조각·심부 표현 때문에 경로 수는 더 많아질 수 있다.
  2. 실제 닫힌 경로 원본을 만든다. 첫 제작 범위는 삼각근 앞·옆·뒤와 광배근·승모근이다. 무채색 인체 위에 이 근육들의 경계를 직접 벡터로 그리고 파츠 ID를 붙인다. 모양이 이미 분리된 기존 SVG를 쓰는 경우에도 실제 경로와 분류의 범위를 검토하고 부족한 세부 파츠를 새로 그린다.
  3. 독립 채색으로 원본부터 검증한다. 삼각근 앞부분만 바꿨을 때 옆·뒤가 유지되는지, 광배근만 바꿨을 때 승모근이 유지되는지 실제 SVG에서 확인한다. 이전 PNG를 다시 생성하는 검증은 사용하지 않는다.
  4. 형태 품질을 검토하고 범위를 확장한다. 가슴·팔·복부·둔근·다리와 심부 도식을 같은 방식으로 만든다. 기존 분류 중 그룹·갈래를 합쳐 표시하는 항목은 매핑 사전에 그 정밀도 제한을 명시한다.
  5. 원본에서 런타임 데이터를 내보낸다. SVG ID, path d, 시점, 변환, 클립, 레이어 순서를 검증하며 JSON으로 변환한다. 최적화 후에도 ID와 부위 연결이 유지되어야 한다. 색상이나 필터로 분리한 근육 의미를 추론하지 않는다.
  6. 그 다음 실제 운동 기록을 연결한다. 모든 지원 입력에 처리 규칙과 도형이 있는지 확인한 뒤 기존 리포트 API·화면·공유에 연결한다. 미완성 파츠를 가까운 근육으로 대신 표시하지 않는다.

원본과 프로그램 파일의 책임

  • design/muscle_atlas_master.svg: 향후 제작할 유일한 편집 원본. 고정된 파츠 ID와 닫힌 경로를 포함한다.
  • scripts/export_muscle_atlas.mjs: 향후 원본 구조 검사와 경로 데이터 내보내기. 실행해서 생성한 JSON을 임의로 별도 편집하지 않는다.
  • app/_lib/muscleAtlas.json: 원본에서 내보낸 런타임 데이터. React와 PNG 출력이 동일한 좌표를 사용한다.
  • server/app/muscle_region_mapping.json: 운동 분류 → 집계 키·그림 키 연결 사전. 해부학적 의미와 미지정 정책을 담당한다.

위 파일은 구현 계획의 산출물 정의이며 지금 앱에 생성하지 않았다. 현재 확인한 공개 SVG 경로 자산은 실제로 부위별 경로와 좌우 분리를 가진다. 이를 사용해 고정된 파츠의 색만 바뀌는 구조를 별도 예시로 검증했다. 다만 “어깨”, “등” 같은 그룹 중심이어서 현재 앱의 전면·측면·후면 삼각근과 모든 심부 근육을 그대로 충족하지 못한다. 공개 자산을 최종 원본으로 채택하거나 해당 패키지를 앱에 설치한 것은 아니다.

완료 조건: 빈도 0→1→5일에서 경로와 좌표가 동일하고, 지정한 파츠만 색이 바뀌며, 선택한 파츠가 자신의 부위 키를 반환해야 한다. 그 조건과 참고 수준의 윤곽 품질을 둘 다 충족한 자산을 확보해야 실제 리포트 작업을 시작할 수 있다.

생성 샘플 3장 · 2026-10-14

상체 전면, 등·둔근, 허벅지·종아리를 원본 이미지로 생성했다. 실제 운동 기록이 아닌 가상 빈도다. 그림은 근육의 윤곽과 저·중·고 빈도 차이를 검토하기 위한 PNG 샘플이며, 부위별 경로와 ID가 들어 있는 SVG 자산은 아니다.

샘플에서 확인한 점과 아직 남은 작업

  • 주요 근육을 곡선 윤곽으로 구분하는 그림 품질과, 같은 근육의 1일·3일·5일 채색 차이를 확인할 수 있다.
  • 등·둔근과 종아리는 표층 그림과 심부 도식을 나눠 표현했다. 각 심부 경계와 라벨의 정확성은 제품 원본 입고 전에 별도로 검토해야 한다.
  • 이번 PNG에는 섬유선과 명암이 비교적 많이 들어 있다. 실제 빈도 지도에서는 섬유선 밀도와 명암을 줄이고 설정된 HEX로 불투명 fill을 적용해 색상 비교를 일정하게 만든다.
  • 생성 이미지의 채색은 팔레트를 시각적으로 참고한 결과다. 픽셀 단위로 지정 HEX와 같거나, 반복 도형의 경로가 완전히 같다고 보장하지 않는다. 실제 SVG 구현에서 동일 경로와 색상 값을 고정한다.
  • 다음 자산 작업은 이 방향의 윤곽을 근육별 닫힌 벡터 경로로 정리하고 앞·뒤·심부 도식의 부위 ID를 연결하는 것이다. 생성된 PNG 자체에 실제 기록의 색을 다시 입히는 작업은 이번에 하지 않았다.

2. 이미지를 어떻게 준비할 것인가

참고 이미지에서 가져올 기준: 몸통을 큰 색 덩어리로 나누는 수준이 아니라, 승모근·광배근·삼각근·둔근·허벅지·종아리가 각자의 해부학적 윤곽으로 보이는 수준이다. 색을 제거해도 위치와 형태로 구분되어야 한다.

전면·후면 두 도식을 같은 비율로 제작한다. 겹쳐 보이는 근육은 별도의 심부 도식에서 보여준다. 포즈에는 작업 시간을 쓰지 않고, 앞·뒤에서 근육 경계가 확인되는 정도만 확보한다.

이 첨부 이미지는 품질 참고로만 사용한다. 잘린 사진을 확대하거나 자동 영역 분할한 결과를 제품 자산으로 사용하는 방식은 권장하지 않는다. 원본의 앞면이 없고, 서로 겹치는 근육의 전체 경계도 얻을 수 없기 때문이다.

근육별 닫힌 SVG 경로확대해도 윤곽이 유지되고 부위마다 색·선·패턴을 바꿀 수 있다. 터치 선택과 공유에 같은 도형을 쓴다.첫 버전 권장. 품질은 원본 벡터의 정확도에 달려 있다.

3. 벡터 좌표·레이어·ID 계약

전면·후면은 각각 동일한 viewBox="0 0 360 760"을 기준으로 한다. 이 수치는 제작 시작점이며, 최종 원본 비율이 확정되면 두 시점과 모든 경로를 함께 고정한다. 심부 확대 도식은 별도의 view_key와 좌표계를 가진다. 화면 크기에 따른 확대는 SVG 전체에 한 번만 적용한다. MDN: viewBox

01 · BASE기본 인체무채색 실루엣, 관절·힘줄·색칠하지 않는 영역. 근육 색을 넣어도 체형과 비율이 유지된다.
02 · REGION근육 면근육별 닫힌 경로. 확인된 빈도에 따른 불투명 채색. 근육끼리 색이 섞이지 않는다.
03 · DETAIL경계·섬유선색 위에 공통 윤곽과 얇은 방향선을 유지한다. 강한 명암·반사광은 빈도 차이를 가리므로 억제한다.
04 · STATE상태·선택미지정 점선 범위, 데이터 부족 사선, 선택 테두리. 실제 빈도 색과 다른 뜻을 가진다.

집계 키와 그림 키를 분리

  • region_key: 기록을 집계하는 표준 부위. 예: latissimus_dorsi.
  • shape_key: 그림의 한 조각. 예: back_left_latissimus_dorsi.
  • view_key: front_surface, back_surface, back_deep 등.
  • side: 사람의 해부학적 좌·우 기준. 앞면에서는 화면 오른쪽이 사람의 왼쪽이다.
  • 한 부위가 좌·우, 앞·뒤, 여러 근육 조각에 등장해도 같은 region_key의 집계 한 건을 참조한다.

런타임 자산에 필요한 데이터

  • atlas_version, 시점별 view_box.
  • shape_key, region_key, view_key, side, path_d.
  • layer_key, draw_order, 확대·회전이 필요할 때의 고정 변환.
  • outline_paths, fiber_paths, group_boundary_paths, 필요한 클립 경로.
  • 라벨 좌표와 터치 보조 경로는 채색 경로와 분리한다. 장식 경로는 선택 이벤트를 가로채지 않는다.

그룹과 세부 부위가 동시에 기록된 경우

대흉근 전체 기록 1일과 윗가슴 기록 2일이 있으면 대흉근 그룹은 날짜 합집합으로 계산한다. 같은 날이 겹치면 총 2일일 수 있다. 그림에서는 윗가슴의 확인된 색을 유지하고, 전체 기록은 대흉근 그룹 경계에 빈도 색의 점선과 “전체 타겟 N일”로 표시한다. 나머지 구역에는 “세부 미지정” 상태를 적용한다. 부모 기록을 자식 구역의 직접 빈도로 복사하지 않는다.

이두 장두·단두와 삼두 세 갈래는 첫 버전에서 근육 전체 그룹으로 합친다. 이는 의도적으로 제한한 표시 정밀도다. 각 갈래의 누락 여부는 그림이 아니라 기록 근거 목록에서 확인하며, 갈래별 그림은 원본과 해부학 검토가 확보된 뒤 확장한다.

세부 분류가 없거나 지원 범위 밖인 경우

  • “등”만 기록: 등 전체 그룹 경계에 빈도 색의 점선과 횟수를 표시한다. 광배근·승모근·능형근을 모두 채우지 않는다. 각 세부 부위는 “세부 미지정”으로 남긴다.
  • “전신”만 기록: 전신 미지정 카드와 점선 범위로 처리한다. 모든 근육의 누락 후보를 없애지 않는다.
  • 분류 없음·알 수 없는 문자열·삭제된 종목: 매핑 불가 목록으로 집계하고 해당 세트를 제외했다는 근거를 표시한다. 기본 부위로 강제 배정하지 않는다.
  • 현재 분류에 없는 근육: 예를 들어 전거근 등은 그림의 무채색 참고 구조로만 두거나 표시 대상에서 제외한다. 기록 입력도 지원하지 않는데 “0회·놓친 근육”으로 표시하지 않는다. 필요하면 먼저 분류 확장 작업을 별도로 정의한다.
  • 좌우 기록 없음: 좌·우를 같은 색으로 보여주고 “좌우 통합”이라고 표시한다. 이 화면으로 좌우 운동 불균형을 판단하지 않는다.

심부 여부와 주요 위치 검토 자료: 등·목, 복부, 어깨·팔, 골반·다리. 표의 제품 매핑과 그룹 단순화는 이 자료를 참고한 설계안이며, 검토를 마친 제품 자산은 아니다.

5. 빈도의 정의와 중복 제거

기본 지표는 “그 부위를 타겟으로 기록한 서로 다른 운동일 수”다. 세트 수·반복 수·중량은 근거 카드의 보조 정보로 남긴다. 같은 날 한 부위 20세트를 한 것이 서로 다른 3일에 운동한 것보다 더 높은 “빈도”가 되면 기능의 의미가 바뀐다.

training_days(region_key)
  = 완료된 세션 중 선택 기간 안의 유효 기록을 해당 부위에 연결한
    workout_date의 집합 크기

집계 범위: period_start ≤ workout_date ≤ as_of_date
세트 조건: 실제 저장된 완료 세션의 세트, reps > 0, weight_kg ≥ 0
날짜 기준: 앱이 사용자의 지역 날짜로 저장한 workout_date
중복 기준: (region_key, workout_date)

예) 같은 날 광배근 3종목 × 4세트 + 같은 날 두 번째 세션

  • 완료 세션 날짜·세트가 있는 날짜는 각각 날짜 합집합으로 센다. 같은 날 두 세션이 있어도 날짜 지표에서는 하루다.
  • 신규 근육 집계는 기간 안의 원본 세트 행에서 계산한다. 기존 preferences.session_count 여러 개를 더하지 않는다.

  • 현재 모델에는 워밍업·주세트 구분이 없다. 첫 버전은 저장된 양수 반복 세트를 포함하고, 워밍업을 자동 추정해서 제외하지 않는다.
  • 벤치프레스의 삼두, 스쿼트의 둔근처럼 보조 참여가 예상되어도 입력한 타겟 이외의 근육에 0.5회 같은 임의 점수를 주지 않는다. 다중 타겟 입력은 후속 데이터 모델 작업이다.
  • 전면·후면·심부 도식은 표현의 차이일 뿐이다. 도식 수나 경로 수가 빈도에 영향을 주지 않는다.

주간과 월간에 똑같이 “5일 이상 진한 색”을 적용하면 월간 지도는 쉽게 전부 진해진다. 달력상 전체 기간을 7일 단위로 환산하되 실제 표시 횟수는 원래 운동일 수로 남긴다. 월마다 범례의 날짜 구간은 기간 길이로 계산한다.

진행 중인 리포트: 집계는 기준일까지의 기록만 포함하고, 색상의 분모는 선택한 전체 주·월 길이로 고정한다. 월요일 한 번의 기록이 주당 7회로 보이거나, 날짜가 지났다는 이유만으로 같은 기록의 색이 옅어지는 현상을 방지한다. 제목에 “진행 중 · 누적”을 표시하고 낮은 색과 0일을 최종 누락 판정으로 사용하지 않는다.

  • 리포트별 최댓값 정규화를 하지 않는다. 전신에서 단 한 부위만 1일 기록했다고 가장 진하게 표시하지 않는다. 1일은 어느 주에도 낮은 단계다.
  • 높은 단계는 “더 자주 기록”이라는 뜻이다. 더 좋은 운동, 더 강한 자극, 더 높은 성장, 권장 횟수를 뜻하지 않는다.
  • 색은 불투명 고정 HEX로 적용한다. CSS 불투명도만 올리는 방식은 배경과 명암에 따라 근육별로 다르게 보인다.
  • 지도 내부는 라이트·다크 테마 모두 동일한 밝은 중립 배경을 사용한다. 주변 카드만 앱 테마를 따른다. 동일 색이 동일 빈도로 보이도록 배경을 고정한다.
  • 첫 버전은 5단계로 차이를 강조하고 정확한 값은 탭·목록에 둔다. 같은 단계 안의 근소한 차이를 연속 그라데이션으로 억지 표현하지 않는다.
  • 텍스트는 색면 위에 직접 얹기보다 옆의 근거 카드에 둔다. 공통 근육 경계선은 #292E32를 초기값으로 두어 가장 진한 단계에서도 3:1 이상의 선·면 대비를 확보한다. 선택선·범례는 별도로 대비를 검증하고, 숫자·이름·상태를 함께 제공한다. W3C: 색만으로 정보 전달 금지, W3C: 비텍스트 대비

팔레트는 초기 시안이다. 제안한 5개의 OKLCH 값은 sRGB 범위 안에 들어오는 것을 계산으로 확인했다. 실제 근육 자산에서의 인접 색 구분, 흑백·색각 시뮬레이션과 접근성 통과를 아직 검증한 것은 아니다. 최소 단계와 최고 단계의 밝기 차이를 유지하면서 시각 QA 결과로 조정한다.

7. “놓친 부위”를 잘못 판단하지 않도록 하는 상태

확인된 기록 있음

기록된 운동일에 따른 색. 예: “광배근 3일 · 12세트”. 다른 미지정 기록이 있으면 확인된 하한값임을 근거 카드에 표시한다.

세부 부위 미지정

무채색 근육 면 + 빈도 색의 점선 그룹 경계. 예: “등 3일 · 세부 부위 미지정”. 해당 근육을 0일 또는 3일로 단정하지 않는다.

기록 부족·매핑 불가

사선 패턴과 “확인 불가”. 완료 운동일에 세트가 없거나 분류를 연결할 수 없으면 단순 회색 0일과 구분한다.

0일을 보여줄 수 있는 조건

“0일”은 지원하는 기록 단위에서 명시 타겟 기록이 없다는 뜻이다. “생리적으로 자극이 없었다”는 뜻이 아니다. 해당 부위를 포함할 수 있는 대분류·그룹 미지정 기록, 전체 매핑 불가 기록, 세트 없는 완료 운동일이 있으면 “세부 미지정” 또는 “확인 불가”가 우선한다.

대퇴사두근이나 햄스트링처럼 기록부터 그룹 단위인 경우 0일 여부도 그룹 단위로만 판단한다. 이두 장두·단두처럼 지도에서 합친 하위 분류는 숫자 목록에서 개별 기록을 확인할 수 있지만 지도는 각각의 근육 누락 판정을 하지 않는다.

사용자에게 보여줄 누락 후보 목록

  • 타겟 기록 없음: 해당 기간 명시 타겟 기록 0일이며 관련 불확실성이 없는 지원 부위. 부위별 목록에서 확인한다.
  • 기록 빈도 낮음: 단계 1인 부위. “낮음”은 척도상 구분이며 운동 부족 진단이 아니다.
  • 분류 보완 필요: “등만 지정 2종목”, “전신 1종목”, “매핑 불가 3세트”. 근육을 더 운동할지 결정하기 전에 이 기록을 확인하게 한다.
  • 심부 부위에 기록이 있으면 기본 그림 아래에 “심부 도식에 기록된 부위 N개”를 항상 표시한다. 그림에 안 보인다고 누락으로 착각하지 않게 한다.

고빈도 부위를 칭찬하는 점수판으로 만들지 않는다. 이 기능의 질문은 “색을 더 진하게 만들었나?”가 아니라 “내가 의도한 부위의 기록이 있는가?”이다. 모든 근육의 0일을 경고로 바꾸면 휴식·목표·복합운동을 고려하지 못하는 화면이 된다. 목록 이름은 “확인할 부위”로 한다.

데이터 품질 표시

지도 옆에 완료 운동일 수, 세트 기록이 있는 운동일 수, 지원 정밀도로 연결한 세트 수, 세부 미지정 세트 수, 매핑 불가 세트 수를 표시한다. 날짜는 집합으로, 세트는 한 원본 행을 한 번씩 분류한다. 대퇴사두근처럼 명명된 그룹에 정확히 연결한 기록은 매핑 완료이며, “허벅지”처럼 세부를 알 수 없는 범위 기록과 구분한다. “완료 4일 중 세트 기록 2일”이면 0일 영역을 확정적인 누락 후보로 제시하지 않는다.

서버 상태는 empty·partial·complete로 정리하되 부위별 mapping_precision과 uncertainty_reasons도 보낸다. 전역 품질이 양호하더라도 그룹 안의 특정 세부 근육은 미지정일 수 있다.

8. 리포트 화면 배치와 확인 흐름

  1. 기간 선택 → 기존 리포트 생성. 같은 응답에 근육 빈도 데이터를 함께 받고 별도 네트워크 요청 없이 표시한다.
  2. 개인 리포트 상단 요약 다음에 지도 카드. 상세 아코디언 안에 숨기지 않는다. 제목은 “부위별 타겟 기록”, 설명은 “같은 날 여러 세트는 1일 · 좌우 통합”.
  3. 앞·뒤 지도와 범례. 넓은 화면은 두 시점 나란히, 좁은 화면에서는 앞·뒤 전환 버튼과 충분한 크기의 단일 도식을 사용한다. 뒤쪽 기록과 심부 기록의 개수는 전환 전에도 보여준다.
  4. 근육 또는 목록 항목 선택. 부위 이름, 정확한 운동일 수, 기록 날짜, 세트 수, 연결된 종목, 직접·그룹 매핑, 불확실성 이유를 카드에서 확인한다. 터치·키보드 모두 목록으로 선택할 수 있다.
  5. 표층 / 심부 도식 전환. 심부로 전환하면 해당하는 별도 도식에서 색을 보여준다. 표층 색 위에 다른 근육 색을 반투명하게 중첩하지 않는다.
  6. “확인할 부위” 목록. 기록 없음·저빈도·분류 보완을 분리해서 보여주고 사용자가 기존 종목 분류 편집으로 이동할 수 있게 연결한다. 새 운동 추천 시스템을 이 기능에 섞지 않는다.

부위 선택 시 fill은 유지하고 테두리만 강조한다. 호버는 선택을 돕는 보조 동작이다. 작은 근육에 겹치는 거대 터치 영역을 얹지 않고, 확대 또는 최소 44px 높이의 목록 버튼을 제공한다. 지도 이미지에는 전체 설명과 숫자 목록을 연결한다.

자료가 없는 기간은 전신 0일 지도를 먼저 노출하지 않고 “이 기간에 분석할 타겟 기록이 없습니다”를 보여준다. API가 새 필드를 보내지 않는 구버전 서버도 빈 배열을 0일로 해석하지 않는다.

  • 원본 필드 조회: 개인·공유 종목 중 실제 출처의 대분류·세부 분류를 따로 투영한다. 기존 합성 target_area 조회는 기존 리포트 호환을 위해 유지한다.
  • 매핑 불가 분리: 지도 집계는 기존 valid_sets 필터 전에 매핑 불가 행을 포착한다. 기록이 삭제되지 않았다면 운동 이름·날짜·세트 수를 확인 근거로 보존한다.
  • 단일 색상 규칙: 서버는 정확한 숫자·상태를 제공하고, 화면·공유가 함께 사용하는 프런트 라이브러리에서 같은 색상 단계를 결정한다. 숫자만 받는 곳마다 기준을 다시 작성하지 않는다.
  • 권한·정보 범위: 현재 사용자 제한을 유지한다. 사진·비공개 메모·위치 데이터를 새 응답에 포함할 필요가 없다.

첫 버전은 집계와 정적 벡터만 추가하므로 DB 마이그레이션과 Supabase Storage가 필요하지 않다. 과거 당시 타겟의 보존까지 요구한다면 세트 저장 시 분류 스냅샷을 남기는 후속 작업이 필요하다. 기존 과거 기록에 당시 값을 복원할 근거가 없으므로 현재 분류로 채운 값을 당시 기록이라고 부르지 않는다.

11. PNG·TXT 공유에도 같은 지도를 반영

  1. 동일한 muscle_frequency와 muscleAtlas.json을 사용해 채색·경계·상태가 적용된 앞·뒤 SVG를 만든다.
  2. SVG에 필요한 fill·stroke·패턴·크기·배경을 명시한다. 외부 폰트·이미지·스타일 참조는 넣지 않는다. SVG를 이미지로 쓸 때는 외부 자원 로딩에 제한이 있으므로 자체 완결 형태로 만든다. MDN: SVG 이미지 제약
  3. Blob URL로 이미지를 디코딩한 뒤 기존 1080px 폭 Canvas 안에 앞·뒤를 나란히 그린다. 심부 기록이 있으면 해당 도식 또는 명시된 심부 기록 목록을 추가해 표층에서 빠진 기록을 보존한다.
  4. 범례, 실제 기간·기준일, “타겟 기록 기준 · 좌우 통합”, 미지정·매핑 불가 수치를 함께 인쇄한다. 높이는 지도·심부 정보·줄바꿈에 맞춰 계산한다.
  5. 완료·실패·취소 시 Blob URL을 해제한다. SVG 준비부터 PNG 변환까지 제한 시간을 두고 실패는 기록한다. 기존 수동 재시도 상한 2회를 유지하고 무응답을 무한 대기하지 않는다.
  6. 지도 변환이 실패하면 텍스트 근거를 제공하고 “지도 생성 실패”를 명시한다. 전체 공유 이미지는 실패 상태를 표시한 텍스트 요약으로 생성할 수 있게 하되, 지도 누락을 정상 성공으로 숨기지 않는다.

TXT 파일에는 그림을 넣을 수 없으므로 “광배근 | 3일 | 12세트 | 직접 매핑” 같은 부위별 표와 기록 없는 부위·미지정 그룹을 출력한다. 문서 공유가 지금은 TXT라는 점을 유지하며, PDF·HTML 내보내기는 이번 첫 버전의 필수 범위로 넓히지 않는다.

13. 첫 버전의 범위와 후속 확장

첫 버전에 포함

  • 전면·후면 근육별 벡터와 필요한 심부 도식.
  • 40개 분류 및 대분류만 지정한 기록의 처리.
  • 운동일 빈도, 5단계 색상, 정확한 숫자와 근거.
  • 0일·저빈도·미지정·매핑 불가 확인 목록.
  • 주간·월간·진행 중 기간과 PNG·TXT 공유.

별도 근거와 데이터가 필요한 확장

  • 운동당 여러 직접·보조 타겟 저장.
  • 당시 분류 스냅샷, 좌우 타겟 입력.
  • 이두·삼두 갈래별 검토된 확대 도식.
  • 전거근 등 현재 입력이 지원하지 않는 부위.
  • 목표별 부족 판단·개인별 운동 추천.

우선순위: 근육 원본의 품질 → 정확한 매핑 → 정직한 빈도 집계 → 색상 차이 → 리포트·공유 연결. 고품질 그림을 확보하기 전에 추천 점수나 보조근 가중치부터 만들면, 정확하지 않은 내용을 정교하게 보여주는 기능이 된다.
